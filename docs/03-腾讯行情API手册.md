# 03 · 腾讯行情 API 手册（实测版）

> 本文所有字段下标都是**对着真实响应逐个核对过**的，不是从别处抄来的。
> 核对时间：2026-09 · 样例：`sh600519`（贵州茅台）、`hk00700`（腾讯控股）。

## 接口总览

| 用途     | 地址                                                              | 编码    | 格式           |
| -------- | ----------------------------------------------------------------- | ------- | -------------- |
| 实时快照 | `https://qt.gtimg.cn/q=<代码列表>`                                | **GBK** | 类 JS 变量文本 |
| 当日分时 | `https://web.ifzq.gtimg.cn/appstock/app/minute/query?code=<代码>` | UTF-8   | JSON           |
| 五日分时 | `https://web.ifzq.gtimg.cn/appstock/app/day/query?code=<代码>`    | UTF-8   | JSON           |
| K 线     | `https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=<参数>` | UTF-8   | JSON           |
| 搜索联想 | `https://smartbox.gtimg.cn/s3/?v=2&q=<关键词>&t=all`              | **GBK** | 类 JS 变量文本 |

**代码格式**：`<市场前缀><代码>`，前缀为 `sh` / `sz` / `bj` / `hk` / `us`。
例如 `sh600519`、`sz300750`、`hk00700`。

**通用注意事项**：

- 必须带 `User-Agent`；建议带 `Referer: https://gu.qq.com/`（接口有弱校验）。
- 实时接口支持一次请求多只，用英文逗号分隔（本项目分批，每批 ≤ 60 只）。
- **不要给 JSON 接口加 `&_var=xxx` 参数** —— 一旦带上，配合返回的就不是纯 JSON，而是
  `var xxx={...}` 形式的 JSONP，`JSON.parse` 会直接失败。这是本项目真实踩过的坑。
- 非交易时段接口依然可用，返回上一交易日的收盘数据。

## 一、实时快照 `qt.gtimg.cn`

### 请求

```
GET https://qt.gtimg.cn/q=sh600519,sz000001,hk00700
```

### 响应

```
v_sh600519="1~贵州茅台~600519~1252.57~1257.12~1259.00~25017~...~";
v_sz000001="...";
```

每个代码一行，形如 `v_<代码>="字段0~字段1~...~字段N";`，字段以 `~` 分隔。
匹配不到代码时会返回 `v_pv_none_match="1";`。

## 二、当日分时 `minute/query`

### 请求

```
GET https://web.ifzq.gtimg.cn/appstock/app/minute/query?code=sh600519
```

### 响应结构

```jsonc
{
  "code": 0,
  "data": {
    "sh600519": {
      "data": {
        "date": "20260921",
        "data": [
          "0930 1259.00 241 30341900.00",
          "0931 1256.46 1243 156138386.00",
          // …
          "1500 1252.57 25017 3136550118.69"
        ]
      }
    }
  },
  "qt": { "sh600519": ["1", "贵州茅台", "600519", "1252.57", "1257.12", "1259.00"] }
}
```

每一行是：`HHMM 价格 累计成交量 累计成交额`。

**要点**：

1. **成交量与成交额都是「当日累计值」，不是每分钟增量。**
   画成交量柱时必须自己相邻相减。
2. **均价 = 累计成交额 ÷ 累计成交股数**。
   A 股累计成交量单位是「手」，所以要 `× 100` 换算成股；港股是股，系数为 1。
   校验：`30341900 ÷ (241 × 100) = 1259.00`，与当时价格一致。
3. **昨收**从同一响应里的 `qt.<代码>[4]` 取，不用再发一次实时请求。
4. **横轴构图**：A 股一天 241 个分钟点（09:30–11:30 共 121 点 + 13:01–15:00 共 120 点）。
   本项目固定按 240 个间隔铺满横轴，盘中只画到当前时刻，右侧留白——
   这才是真实分时图的样子，而不是把已有数据拉伸铺满。
5. 收盘后接口会继续补出 15:00 之后的重复点位，本项目会过滤掉
   `>1500` 以及午休时段（`1131–1300`）的行。

## 三、五日分时 `day/query`

### 请求

```
GET https://web.ifzq.gtimg.cn/appstock/app/day/query?code=sh600519
```

### 响应结构

```jsonc
{
  "code": 0,
  "data": {
    "sh600519": {
      // 注意：是**数组**（不是按日期作键的对象），而且顺序是「新 → 旧」
      "data": [
        { "date": "20260921", "data": ["0930 1259.00 241 30341900.00", "..."] },
        { "date": "20260918", "data": ["0930 1262.99 113 14271787.32", "..."] },
        { "date": "20260917", "data": ["..."] },
        { "date": "20260916", "data": ["..."] },
        { "date": "20260915", "data": ["..."] }
      ],
      "qt": { "sh600519": ["1", "贵州茅台", "600519", "1252.57", "1257.12", "1259.00"] },
      "mx_price": { "price": [], "mx": [] }
    }
  }
}
```

每天的 `data` 行格式与当日分时完全一致（`HHMM 价格 累计成交量 累计成交额`），
所以解析逻辑可以直接复用。

**要点**：

1. **日期顺序是倒的**：`data[0]` 是最新的一天，画图前要反转成「左旧右新」。
2. **每天的昨收接口没有直接给**，需要推导：
   - 最新一天的昨收 = `qt[4]`（权威值）；
   - 更早的那些天，昨收 = **比它再早一天的最后成交价**
     （数组是倒序的，所以 `data[i]` 的前一交易日就是 `data[i+1]`）；
   - 最早的那一天没有更早数据可用，退化成用当天首个分时价当基准——
     这只会影响那一天线段的上色，不影响价格本身。
3. **每天的成交量都是从 0 重新累计的**，所以「累计转增量」必须**按天分别做**，
   不能把五天串成一条流水线。
4. 五日分时没有统一的涨跌幅基准，本项目只用价格刻度
   （`docs/04-UI设计系统.md` 里有构图说明）。

## 四、K 线 `fqkline/get`

### 请求

```
GET https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh600519,day,,,160,qfq
```

`param` 的格式是：`代码,周期,起始日期,结束日期,数量,复权方式`

| 位置 | 取值                          | 说明                       |
| ---- | ----------------------------- | -------------------------- |
| 周期 | `day` / `week` / `month`      | 日 / 周 / 月               |
| 日期 | 留空                          | 留空表示以最新交易日为终点 |
| 数量 | 如 `160`                      | 取多少根                   |
| 复权 | `qfq`（前复权）/ `hfq` / 留空 | 做技术分析一律用前复权     |

### 响应结构

```jsonc
{
  "code": 0,
  "msg": "",
  "data": {
    "sh600519": {
      "qfqday": [
        ["2026-09-14", "1277.270", "1277.960", "1285.530", "1270.360", "16571.000"],
        ["2026-09-21", "1259.00", "1252.57", "1259.95", "1250.80", "25017"]
      ],
      "qt": { "sh600519": ["1", "贵州茅台", "600519", "1252.57", "1257.12", "1259.00"] },
      "prec": "1257.12"
    }
  }
}
```

每根 K 线是 `[日期, 开, 收, 高, 低, 成交量(手)]`。

**要点**：

1. **返回的键名跟复权方式绑定**：前复权是 `qfqday` / `qfqweek` / `qfqmonth`，
   不复权才是 `day` / `week` / `month`。
   本项目两种都兼容：`body['qfq' + period] ?? body[period]`。
2. 最后一根（当日）的成交量可能是整数 `25017`，历史数据是 `"16571.000"`，
   统一用 `Number()` 转换即可。
3. 注意顺序是 **开、收、高、低**，不是常见的 OHLC——写错会导致 K 线实体上下颠倒。

## 五、搜索联想 `smartbox`

### 请求

```
GET https://smartbox.gtimg.cn/s3/?v=2&q=<URL 编码的关键词>&t=all
```

### 响应

```
v_hint="sh~600519~贵州茅台~gzmt~GP-A^sz~000858~五粮液~wly~GP-A";
```

- 条目之间用 `^` 分隔，字段之间用 `~` 分隔；
- 字段依次是：`市场 ~ 代码 ~ 名称 ~ 拼音缩写 ~ 证券类型`；
- 无结果时返回 `v_hint="N";`；
- 拼音搜索也支持（`q=gzmt` 能搜到贵州茅台）。

**要点**：

1. 响应是 **GBK**，必须解码后再匹配，否则中文名全是乱码；
2. 关键词要做 URL 编码（`encodeURIComponent`）；
3. 结果可能以 `^` 结尾，切分后要过滤空串；
4. `t=all` 表示搜索全部类型（股票/指数/基金/债）。类型字段常见值：
   `GP-A`（A 股）、`ZS`（指数）、`JJ`（基金）、`GP-B`（B 股）。

## 七、稳定性建议

| 风险                      | 对策（本项目已实现）                                             |
| ------------------------- | ---------------------------------------------------------------- |
| 上游字段下标随市场变化    | 按市场分派解析函数，缺失字段一律降级为 `undefined`，界面显示 `—` |
| 网络抖动导致重试风暴      | TTL 缓存 + **同 key 并发请求合并**（`TtlCache.resolve`）         |
| 请求过于频繁被限流        | 交易时段按用户间隔，盘后自动降频到 ≥30 秒；窗口不可见时暂停      |
| 停牌 / 未开盘导致价格异常 | 最新价为 0 时用昨收兜底，避免出现 `-100%` 的离谱涨跌幅           |
| 接口改版                  | 解析层是纯函数，可随时拿真实报文补测试用例                       |
