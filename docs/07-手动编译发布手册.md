# 07 · 手动编译发布手册

> **平台范围（2026-10-30 用户指令）**：只做 **Linux**；Windows / macOS 章节仅作历史参考，不再验收、不再打包。当前 Linux 产物见文末「Linux 发布存档」。

> 这份手册**目前只覆盖桌面端（Electron）**的 exe 发布。
> Web 端与 Python 服务的发布方式（静态资源 + 后端进程/Docker、鉴权、端口）
> 尚未确定，v0.7 落地后补进本文件；不要提前按不存在的命令操作。
>
> 这份手册只回答一个问题：**从「代码改完了」到「把 exe 交到别人手里」，
> 每一步怎么做、怎么确认这一步做对了。**
>
> 全流程都是**手动执行、逐步确认**的。发布与日常开发不同：
> 产物一旦发出去，发现问题只能发新版本覆盖，所以宁可慢、不可跳步。

**平台策略：代码保持 Windows/Linux/macOS 跨平台，但每个系统必须在自己的机器上构建，不做交叉编译。**
当前自动化只验证 Linux；Windows/macOS 命令见下方章节，需在对应系统实机验收。

本文的 **Linux 部分逐条实测过**（实测数据见第八节）；
Windows / macOS 只给命令，**未在本会话验证**。

## 一、先建立心智模型：五个容易搞混的点

| 你以为                     | 实际                                                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `npm run build` 就是在打包 | 它只生成 `out/`（JS / CSS / HTML）。**真正把 Node + Chromium 运行时和 `out/` 塞进一个 exe 的是 `electron-builder`** |
| exe 是项目的一部分         | `release/` 在 `.gitignore` 里。exe 是**发布附件**，不进版本库 —— 别人 clone 下来拿不到，必须单独给                  |
| 版本号要改好几个地方       | **只改 `package.json`**。`electron-builder.yml` 用的是 `${version}` / `${name}` 占位符，会自动跟着变                |
| 打包不需要网络             | 需要。要下载 Electron 二进制与 NSIS 工具链，而且是**两套互不相干的下载器、两个镜像键**                              |
| 编译、提交、发布是一件事   | 是三件独立的事：`build` 只在本地产出文件 → `commit` 进版本库 → `tag` / `push` 才是对外发布                          |

## 二、环境前置（出问题十有八九在这一节）

### 2.1 一律用 `npm.cmd`，不要用 `npm`

Windows PowerShell 默认禁止执行脚本，而 `npm` 在 PowerShell 里走的是 `npm.ps1`，
会直接报 `npm.ps1 cannot be loaded because running scripts is disabled`。

```powershell
npm.cmd -v          # 能打印版本号就对了
```

本文所有命令都写成 `npm.cmd`。想一劳永逸也可以放开执行策略
（`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`），见 `docs/01`。

### 2.2 先修 PATH，并清掉 `ELECTRON_RUN_AS_NODE`

若 `node -v` 报的版本不对、或应用窗口**根本不出现**，在同一个终端里先执行：

```powershell
$env:Path = 'C:\Program Files\nodejs;' + $env:Path
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
```

- 前半句：某些终端环境里 PATH 被别的 `node` 垫片挡住，必须把真 Node 排到最前；
- 后半句：`ELECTRON_RUN_AS_NODE=1` 会让 Electron **退化成纯 Node 进程**——
  不报错、不崩溃，只是**永远不出窗口**，截图工具会一直等到超时。
  这是排查「界面打不开」时最容易忽略的一条。

### 2.3 确认镜像「两件套」都在

打包要下载两类东西，由 `.npmrc` 里两个**不同的键**控制，缺一不可：

```powershell
Get-Content .npmrc
```

| 键                                 | 管什么                             |
| ---------------------------------- | ---------------------------------- |
| `electron_mirror`                  | Electron 运行时二进制（约 235 MB） |
| `electron_builder_binaries_mirror` | NSIS / winCodeSign 等打包工具链    |

> 注意：`electron_custom_dir={{ version }}` 也是必须的 ——
> npmmirror 的目录结构是 `/44.4.3/`，而 GitHub 是 `/v44.4.3/`，
> 少了这一行会 404。

### 2.4 不要用管道判断成败

```powershell
npm.cmd run check | Select-Object -Last 5   # ← 这样读 $LASTEXITCODE 不可靠
```

管道会掩盖真实退出码。要判断成败就重定向到文件：

```powershell
npm.cmd run check *> $env:TEMP\check.log
Write-Host "exit=$LASTEXITCODE"             # 这才是真的
Get-Content $env:TEMP\check.log -Tail 20
```

### 2.5 本机实测基线（对照用）

| 项目             | 本机实测值                   |
| ---------------- | ---------------------------- |
| Node.js          | `v24.21.0`（要求 ≥ 20.19）   |
| npm              | `11.19.0`                    |
| git              | `2.49.0.windows.1`           |
| Electron         | `44.4.3`                     |
| `build:win` 耗时 | **约 22 秒**（工具链已缓存） |

> 首次打包要下载工具链，时间取决于网络，可能到 1~2 分钟。
> 之后走缓存，稳定在 20 秒出头。

## 三、发布流程（八步）

### ① 决定版本号

遵循语义化版本：加功能 +1 minor，只修 bug +1 patch。

> **本项目额外约定**：只改文档 / 工程配置时**不单独发版**。
> 因为源码没变，发出来的 exe 与上一版**内容完全相同**——
> 让人重新下载一个一模一样的文件是种欺骗。

### ② 改 `package.json` 的 `version`

一处生效，产物文件名与 `release/<版本号>/` 目录都会跟着变。
改完顺手确认 `electron-builder.yml` 里没有写死的版本号（本项目用的是占位符）。

### ③ 更新 `CHANGELOG.md`

把「未发布」小节里的内容归到新版本号下，写清日期与主题
（格式参考文件顶部的说明）。**实测数据要放进来**，第九节（本次发布）与第八节（上一版）都是范例。

### ④ 健康检查

```powershell
npm.cmd run check
```

必须 **exit 0**。它依次跑类型检查、ESLint、TS 单元测试（当前 157 个）、
Python 协议测试（17 个）。**开发机必须能跑 `python3`（或 `python`）**，
否则 `test:python` 会失败。

**顺带核对一件事**：测试数量与文档里写的是否一致。
本项目真的踩过这个坑 —— 文档写着 139，实际已经是 147（后来又涨到 163、179、192、196；
v0.6 删掉腾讯解析后是 157 + 17 Python），
因为文档是照批次中间状态的数字写的。

### ⑤ 打包

**先确认 Nuitka 可用**（只需一次；Linux 还需 patchelf）：

```bash
python3 -m pip install -r requirements.txt
python3 -m nuitka --version
patchelf --version
```

**不要从 Linux 交叉打 Windows 包**：`electron-builder --win dir` 会把当前平台的
`python/dist/tdx-bridge`（ELF）原样塞进 Windows 包，启动必失败。现在
`scripts/before-pack.cjs` 会在打包前校验 sidecar 魔数并直接报错；Windows
包必须在 Windows 上运行 `npm.cmd run build:win`。

`build:win` 会自动先跑 `npm run build:python`，把 `python/tdx_bridge.py`
打成 `python/dist/tdx-bridge.exe`，再交给 electron-builder 放进
`resources/tdx-bridge/`。

```powershell
npm.cmd run build:win            # 安装包 + 便携版，一次出两个
npm.cmd run build:win:portable   # 只要单文件便携版
npm.cmd run build:win:setup      # 只要 NSIS 安装包
```

如果只想先验证桥接程序，可以单独跑：

```powershell
npm.cmd run build:python
python\dist\tdx-bridge.exe       # 应该等到一行 JSON 输入；Ctrl+C 退出
```

产物落在 `release/<版本号>/`：

```
release/0.5.0/
├── stocklens-0.5.0-portable.exe      ← 单文件便携版（交付物）
├── stocklens-0.5.0-setup.exe         ← NSIS 安装包（交付物）
├── stocklens-0.5.0-setup.exe.blockmap
├── builder-debug.yml                 ← 打包参数快照，排查用
├── win-unpacked/                     ← 未压缩目录，调试用
└── StockLens-data/                   ← 跑过便携版后，它的数据存这儿
```

### ⑥ 实测产物（**这一步绝对不能省**）

打包命令返回 0 **不等于**产物能用。分三小步。

**(a) 让便携版自己截图**

应用内置了截图开关（`src/main/capture.ts`），设了环境变量才生效：

```powershell
$exe = 'release\0.5.0\stocklens-0.5.0-portable.exe'
$env:STOCKLENS_CAPTURE       = "$PWD\screenshots\portable.png"
$env:STOCKLENS_CAPTURE_DELAY = '5000'      # 给行情请求留 5 秒
$p = Start-Process $exe -PassThru
$p.WaitForExit(120000) | Out-Null
Write-Host "exit=$($p.ExitCode)"
```

**(b) 测启动耗时（方法要正确）**

```powershell
$env:STOCKLENS_CAPTURE_DELAY = '0'
$sw = [Diagnostics.Stopwatch]::StartNew()
$p  = Start-Process $exe -PassThru
$p.WaitForExit(120000) | Out-Null
$sw.Stop()
Write-Host ("{0:N2} 秒" -f $sw.Elapsed.TotalSeconds)
```

两条必须知道的规矩：

- **`delay=0` 时退出码是 1、也不会产出截图** —— 这是预期行为，不是崩溃。
  延迟为 0 时 `capturePage()` 在页面合成首帧前执行，会抛 `UnknownVizError`
  （`docs/06` 第 21 条）。此时进程早已打印过 `[main] 配置文件：…`，说明启动正常。
  这样测到的是「双击 → 页面加载完成」。
- **绝不要把 `delay=5000` 的墙钟时间当启动耗时** —— 那等于把 5 秒等待算进去了。
  本项目第一次就是这么量出「便携版要 6 秒」的错误结论并写进文档的（`docs/06` 第 20 条）。

**(c) 确认没有留下垃圾**

```powershell
Test-Path "$env:TEMP\StockLensPortable"    # 正常退出应为 False
```

便携版每次启动都会把约 368 MB 解压到这个目录，正常退出时清理，
**被强杀（任务管理器结束进程）时会残留**，手动删掉即可。

**(d) 肉眼验收截图**

打开 `screenshots/portable.png`，重点看：

- 不是白屏、深色底纹正常；
- 涨跌颜色符合 A 股语义（**涨红跌绿**）；
- 自选股名字没有多余空格（通达信也会拿空格做对齐填充，如 `五 粮 液`，Python 侧已归一化）；
- 图表区有内容、没有画歪或溢出。

> 类型检查与单元测试永远抓不到「布局错位、颜色不可读」，
> 只有这一步能。这是 `PRINCIPLES.md` 里 U5 存在的理由。

### ⑦ 记录实测数据并提交

把产物大小、启动耗时、临时目录行为写进 `CHANGELOG.md` 的「已验证」小节。
**数字必须实测后填**，不要估算 —— 第八节的表格就是范例。

提交前先看一眼改了什么：

```powershell
git status --short
git add -u                                   # -u 只提交已跟踪文件的修改
```

中文提交信息**建议走文件**，别直接写在 `-m` 后面：

```powershell
# 用编辑器把提交信息写进 .commit-msg.tmp（UTF-8），然后：
git commit -F .commit-msg.tmp
Remove-Item .commit-msg.tmp
```

原因：本机终端环境的默认编码不是 UTF-8（`Get-Content` 会把 UTF-8 文件读成乱码），
中文直接当参数传给 git 有被写坏的风险。写成文件可控得多。

### ⑧ 打标签与推送（**对外动作，先确认再做**）

```powershell
git tag v0.5.0                    # 打标签（本地）
git ls-remote --tags origin       # 先看远端到底有没有标签
git push origin master            # 推分支
git push --tags                   # 推标签
```

- 这一步之后东西就对外可见了，**做之前先问过负责人**；
- `git push` 与 `git push --tags` 是两条独立命令，**只推分支不会带上标签**；
- 远端没有任何标签时，GitLab 上就没有可下载的 Release 页面 ——
  想让别人直接下 exe，需要建 Release 并**手动上传产物文件**
  （`release/` 不进版本库，推送不会带上去）。

> **重发同一个版本时会遇到**：`git tag v0.5.0` 报 `already exists`。
> 想让它指向新提交，得先 `git tag -d v0.5.0` 再重打。
> **只有确认远端还没有这个标签时才是安全的**（远端有的话就是改写历史，会影响别人）。

## 四、熟练以后：一次性命令块

```powershell
# ---- 0. 环境 ----
$env:Path = 'C:\Program Files\nodejs;' + $env:Path
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue

# ---- 1. 健康检查（必须 exit 0）----
npm.cmd run check *> $env:TEMP\check.log
if ($LASTEXITCODE -ne 0) { Get-Content $env:TEMP\check.log -Tail 30; throw '检查未通过' }

# ---- 2. 打包 ----
npm.cmd run build:win

# ---- 3. 实测启动耗时（3 次求稳）----
$exe = 'release\0.5.0\stocklens-0.5.0-portable.exe'
$env:STOCKLENS_CAPTURE_DELAY = '0'
1..3 | ForEach-Object {
  $sw = [Diagnostics.Stopwatch]::StartNew()
  $p  = Start-Process $exe -PassThru
  $p.WaitForExit(120000) | Out-Null
  $sw.Stop()
  Write-Host ("第 {0} 次：{1:N2} 秒（退出码 {2}，delay=0 时 1 属预期）" -f $_, $sw.Elapsed.TotalSeconds, $p.ExitCode)
}

# ---- 4. 截图验收 ----
$env:STOCKLENS_CAPTURE       = "$PWD\screenshots\portable.png"
$env:STOCKLENS_CAPTURE_DELAY = '5000'
$p = Start-Process $exe -PassThru; $p.WaitForExit(120000) | Out-Null
Write-Host "截图退出码 $($p.ExitCode)（0 才对）→ 打开 screenshots\portable.png 看一眼"

# ---- 5. 残留检查 ----
Write-Host "临时目录残留：$(Test-Path "$env:TEMP\StockLensPortable")（应为 False）"

# ---- 6. 产物指纹（写进发布记录）----
Get-ChildItem release\0.5.0\*.exe | ForEach-Object {
  Write-Host ("{0}  {1:N2} MB  {2}" -f $_.Name, ($_.Length/1MB), (Get-FileHash $_.FullName -Algorithm SHA256).Hash)
}
```

| SmartScreen / 杀毒拦截              | 应用未做代码签名                         | 已知取舍，见 `PLAN.md` 的 TD7；学习项目可加信任                                  |
