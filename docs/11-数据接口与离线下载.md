# 数据接口与离线下载

> 目标：把通达信可合法读取的 A 股数据尽量完整地落成**可追溯、可重放**的本地数据，
> 供 Python/机器学习使用。交易下单、付费授权数据、7727/EX 不在范围内。

## 3. 已实现的读取/回退链路

- K 线请求成功：写 `cache/klines/<code>_<period>_<count>_<adjust>.parquet`，
  列含 `date/open/close/high/low/volume/amount`；旧缓存没有 `amount` 列时仍可读，
  该字段返回 `null`，下一次网络请求会写回完整列；
- 请求失败：自动读同一 key 的缓存，返回 `source=cache`；
- 图表头显示「离线缓存」，不把缓存伪装成实时；
- 缓存显式预热：数据工具「离线 K 线缓存」为当前自选股拉 800 根前复权日 K；
- 全历史：每 800 根分页，`start=0,800,...` 自动探测到空页/短页，按日期去重排序后写 `*_all_none.parquet`；日 K 实测 6,032 根（2001-08-27 起），1 分钟实测 22,320 根（28 页），上证指数实测 8,753 根（1990-12-19 起）；
- 启动缓存优先：行情快照先读本地，图表先读缓存（`cacheOnly`），网络回来再覆盖；
- 主图一次请求 800 根，均线用完整 800 根计算后只裁可见窗口；
- 本地数据清单：数据工具「本地离线数据」扫描 raw/cache/lake/exports/normalized/local；
- K 线缓存清单：同一面板显示文件数、股票数、周期、最近更新时间，便于 ML 任务核对覆盖；
- 统一下载页：可多选日 K / 1 分钟 K / 指数 K / 板块文件 / 快照 / TDX 统计 / 数据湖归档，任务级进度条；
- 增量下载：K 线默认跳过已存在的缓存文件，页面显示「完成 / 跳过 / 失败」计数；
- 三类数据统一：日 K、1 分钟 K、历史逐笔共用「批量下载本地数据」的范围选择、增量跳过、
  进度与取消；历史逐笔按 `trade_date=YYYY-MM-DD/<code>.parquet + manifest` 分区，
  Python 侧 `trades()` 对历史日期先读归档、缺档才回网络；已有有效归档不覆盖；
- 逐笔查询：`0x122F` 秒级为主，失败回退 7709；「全部」按 1,800 条循环分页，
  按绝对 index 去重合并，避免只显示前 1,800 笔；
- 面向 ML：逐笔 JSONL 每行一个 tick，保留 `timeSeconds/price/volume/side/tradeAmount`；
  可用 `pandas.read_json(..., lines=True, compression='gzip')` 读取单日分区；
  K 线缓存本身是 Parquet，含 `amount`（成交额，元），可直接用 DuckDB/Pandas 列式分析；
- 全历史下载同样支持跳过 `*_all_none.parquet`，可断点续跑；`adjust=none` 避免前复权负价；
- 历史涨停复盘：扫描本地日 K 全历史缓存，按涨跌停限制判定指定日的涨停/跌停/炸板；只覆盖已缓存股票。

## 4. 仍然缺的接口（不宣称已做全）

以下缺口按优先级排列，后续需要单独实现并保留真实报文/schema：

1. 全市场历史日 K 批量下载：数据工具已提供「全 A 股」分批缓存，但仍是前台逐批执行，已支持跳过已有缓存做断点续跑；仍缺后台任务与失败重试报表；
2. 历史逐笔/分时的**批量落盘**：单个历史日期已可查（逐笔 MAC 秒级、竞价 0x056a 历史），但还没有全市场批量归档任务；
3. ~~集合竞价历史~~ **已补齐（2026-10-31）**：`0x056a` 支持历史日期，实测 2026-10-28/29/30 返回 106/131/116 点；

## 5. 机器学习数据约定

- 原始层不可变；
- 规范层按 `trade_date` 分区，使用 Parquet + schema 版本；
- 每条数据保留来源、抓取时间、解析器版本、校验和；
- 财务/公告使用公告日/报告期，避免未来函数；
- 退市、停牌、ST 保留，不静默过滤。

## 6. 离线数据备份 / 恢复（2026-11-01）

目标：换机或重装系统时，不再从服务器把几十 GB 的离线数据重新下一遍。

- **范围**：`pythontdx_data_dir()` 整个目录（raw / cache / lake / exports /
  normalized / local），跳过未写完的 `.part`；
- **格式**：单个 `.zip`，条目用相对路径；zip 内附 `_pythontdx_backup.json`
  清单（format / app / createdAt / dataRoot / fileCount / totalBytes）；
  行情文件本身是 Parquet+ZSTD / JSONL.gz，deflate 再压收益接近 0，
  所以用 **STORED** 只做单文件封装，几 GB 也不会卡在压缩上；
- **不覆盖**：目标备份文件已存在时直接报错（备份是用户指定的可移动介质，
  写坏了没有第二次机会）；默认文件名带时间戳；
- **恢复语义**：只补本机缺的文件，已存在的文件一律跳过（规则 12：
  本地数据永久保存、不覆盖有效归档）；zip 条目做 `../`、绝对路径、盘符校验；
  解压先写 `.part` 再 `os.replace`，中断不会留下半个文件；
- **通道**：Python sidecar `backup_create` / `backup_inspect` / `backup_restore`，
  主进程 IPC 超时 2 小时；桌面端用系统对话框选路径，Web 端明确提示不支持；
- **实测（2026-11-01）**：3 个文件（23 B）备份 → inspect 3 / 23 B →
  空目录恢复 3 个；已有文件恢复时 `restored=0 skipped=3`；`../escape.txt`
  备份被拒绝且未写出文件。UI 截图 `screenshots/data-backup.png`。
