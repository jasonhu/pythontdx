# 01 · 快速开始

## 环境要求

| 项目     | 版本                                 | 说明                               |
| -------- | ------------------------------------ | ---------------------------------- |
| Node.js  | ≥ 20.19                              | 推荐 22 LTS 或更高。`node -v` 查看 |
| npm      | ≥ 10                                 | 随 Node 一起安装                   |
| 操作系统 | Windows 10+ / macOS 11+ / 主流 Linux | 三平台均可开发与打包               |

> 不需要预装 Electron、Vite 或任何全局 CLI，所有工具都是项目内依赖。

## 安装与启动

```bash
npm install     # 安装依赖（首次会自动从 npmmirror 下载 Electron 二进制，约 235 MB）
npm run dev     # 启动开发模式
```

`npm run dev` 会做三件事：

1. 用 Vite 构建主进程与 preload 脚本到 `out/`；
2. 启动渲染层的开发服务器（默认 `http://localhost:5173`）；
3. 启动 Electron，主进程崩溃自动重启，渲染层改动热更新（HMR）。

## 全部命令

| 命令                | 作用                                         |
| ------------------- | -------------------------------------------- |
| `npm run dev`       | 开发模式（热更新）                           |
| `npm run build`     | 构建生产产物到 `out/`                        |
| `npm run preview`   | 用生产产物启动一次，验证打包结果             |
| `npm run check`     | **一条命令跑完 类型检查 + Lint + 单元测试**  |
| `npm run typecheck` | 对主进程侧和渲染侧分别做类型检查             |
| `npm run lint`      | ESLint（含 `solid/reactivity` 等响应式规则） |
| `npm run test`      | Vitest 单元测试（`test:watch` 进入监听模式） |
| `npm run shot`      | 构建后启动应用并截图到 `screenshots/`        |
| `npm run icon`      | 重新生成应用图标（纯 Node 手写 PNG/ICO）     |
| `npm run format`    | 用 Prettier 格式化全部源码与文档             |

**打包**

| 命令                         | 作用                                        |
| ---------------------------- | ------------------------------------------- |
| `npm run build:win`          | Windows：**同时**产出安装包 + 单文件便携版  |
| `npm run build:win:portable` | 只要单文件便携版 exe（免安装）              |
| `npm run build:win:setup`    | 只要 NSIS 安装包                            |
| `npm run build:mac`          | 构建 macOS 安装包（dmg，需在 macOS 上执行） |
| `npm run build:linux`        | 构建 Linux 安装包（AppImage / deb）         |

> 提交代码前跑一次 `npm run check`，三件事一次过完。

## 打包与分发

产物统一放在 `release/<版本号>/` 下。

```powershell
npm run build:win
```

跑完会得到：

```
release/0.3.0/
├── stocklens-0.3.0-portable.exe   ← 单文件便携版，106 MB，双击即用
├── stocklens-0.3.0-setup.exe      ← NSIS 安装包
├── win-unpacked/                  ← 未压缩的程序目录（调试用）
└── StockLens-data/                ← 你跑过便携版后，它会把数据写在这里
```

### 两种产物怎么选

|          | 单文件便携版                 | NSIS 安装包            |
| -------- | ---------------------------- | ---------------------- |
| 安装     | 不需要                       | 需要                   |
| 数据位置 | exe 旁边的 `StockLens-data/` | `%APPDATA%\StockLens\` |
| 启动耗时 | **约 2 秒**                  | **约 1 秒**            |
| 卸载     | 删掉 exe 与数据目录，无残留  | 走卸载程序             |

**为什么便携版比安装版慢一点？** 单文件 exe 其实是一个自解压启动器：
每次运行都要把约 368 MB 的内容解压到 `%TEMP%\StockLensPortable`，退出时清理。
实测这个代价约为 **1 秒**（2s vs 1s），比想象中小。

> 想让便携版真正绿色：把 exe 和 `StockLens-data/` 一起拷到 U 盘。
> 换台电脑双击，自选股和设置原样都在。
> 如果 exe 放在只读位置（光盘、`Program Files`），数据会自动落回 `%APPDATA%`。

### 国内网络下打包失败怎么办

打包需要从 GitHub Releases 下载 NSIS 工具链。项目的 `.npmrc` 已经配好镜像：

```ini
electron_builder_binaries_mirror=https://npmmirror.com/mirrors/electron-builder-binaries/
```

如果仍然失败，先删掉缓存再试：

```powershell
Remove-Item "$env:LOCALAPPDATA\electron-builder\Cache" -Recurse -Force
```

### 常见问题

- **杀毒软件报警**：未签名的 Electron 应用常被误报。代码签名需要购买证书，
  学习项目可以忽略，或在本机添加信任。
- **`%TEMP%` 里残留 `StockLensPortable`**：正常退出会自动清理；
  如果应用被强杀（任务管理器结束进程）就会残留，手动删掉即可。
- **打包很慢**：第一次要下载工具链，之后走缓存，通常 1~2 分钟。

## 调试技巧

### 1. 渲染进程：F12 打开 DevTools

开发模式下 `F12` 或 `Ctrl+Shift+I` 打开 DevTools，可以看 DOM、改样式、断点调试 Solid 组件。

### 2. 渲染进程的日志会转发到终端

主进程注册了 `console-message` 监听，界面里的 `console.log / warn / error`
会带着 `[renderer:xxx]` 前缀打到运行 `npm run dev` 的终端里。
**白屏排查第一步就是看终端有没有红色输出。**

### 3. 主进程断点：VS Code

项目自带 `.vscode/launch.json`，在 VS Code 里选
**「Debug: Main + Renderer」** 然后按 F5：

- 主进程代码可以在 `src/main/**` 里直接下断点；
- 渲染层会用自带的 DevTools 打开，也可以在 `src/renderer/**` 下断点。

### 4. 看配置文件落在哪

开发模式启动后终端会打印一行：

```
[main] 配置文件：C:\Users\<你>\AppData\Roaming\StockLens\stocklens.json
```

删掉这个文件就等于「恢复出厂设置」（自选股会回到 6 只示例股票）。

### 5. 只想验证接口，不想开界面

见 [03-腾讯行情API手册.md](03-腾讯行情API手册.md) 末尾的 curl / PowerShell 片段。

### 6. 改完样式，如何确认「真的变好看了」

```powershell
npm run shot                              # 截图到 screenshots/app.png
node scripts/screenshot.mjs out.png 8000  # 自定义路径与等待毫秒数
```

它会先用生产产物构建，再启动 Electron、等界面和数据加载完、截一张图就退出。
**这一步能抓到类型检查和单元测试都抓不到的问题**——比如布局溢出、
颜色不可读、图表画歪。项目里的分时图「昨收为 0」那个 bug 就是这么发现的。

### 7. 单元测试怎么跑单个文件

```powershell
npx vitest run src/main/services/tencent/parse.test.ts
npx vitest            # 监听模式，改代码自动重跑
```

## 常见问题

### `npm.ps1 cannot be loaded because running scripts is disabled`

Windows PowerShell 默认禁止执行脚本，而 npm 在 PowerShell 里会走 `npm.ps1`。三选一：

```powershell
# 方案 A：直接调用 npm.cmd（最省事，不影响系统设置）
npm.cmd install

# 方案 B：为当前用户放开本地脚本执行权限（推荐，一劳永逸）
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# 方案 C：改用 CMD 或 Git Bash
```

### Electron 二进制下载失败 / 卡住

Electron 44 **没有 postinstall 脚本**，它是在第一次被 `require` 时惰性下载的。
项目根目录的 `.npmrc` 已经配置好国内镜像，正常情况无需干预：

```ini
electron_mirror=https://npmmirror.com/mirrors/electron/
electron_custom_dir={{ version }}
```

如果仍然失败，手动触发一次下载：

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_CUSTOM_DIR = '{{ version }}'
node node_modules/electron/install.js
```

### 界面是白的，但终端没有任何报错

按顺序排查：

1. 终端里是否出现 `[renderer:error]` 或 `页面加载失败`；
2. F12 打开 DevTools，看 Console 与 Network；
3. 确认 `src/preload/index.d.ts` 里的 `Window.api` 声明与 `src/preload/index.ts` 的实际导出一致；
4. 检查 `out/preload/index.js` 是否被正确生成（`npm run build` 之后看这个文件在不在）。

### 行情不刷新

- 底部状态栏的指示灯：「实时」= 正常，「连接异常」= 看后面的错误文案；
- 非交易时段主进程会自动降频到 30 秒以上，这是**有意设计**，不是卡死；
- 窗口最小化时默认暂停请求（可在设置里关闭）。
