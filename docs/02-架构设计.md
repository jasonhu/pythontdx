# 02 · 架构设计

> 本文件同时描述**现状**与**目标**，两者必须分清：
> 现状是 v0.6（Electron 桌面 + Python stdio sidecar），
> 目标是 v0.7+（桌面 + Web 双前端 + Python HTTP/WS 后端）。
> 目标与范围以 `docs/00-项目章程.md` 为准；迁移任务在 `PLAN.md` 的 P0。

---

## 一、目标总览：两个前端，一个后端

```
┌────────────────────┐        ┌────────────────────┐
│ Electron 桌面壳     │        │ 浏览器 Web          │
│ 窗口/托盘/更新/权限 │        │ 静态页面 + 浏览器 API│
└─────────┬──────────┘        └─────────┬──────────┘
          │   HTTP / WebSocket（同一套契约）│
          └───────────────┬──────────────┘
                          ▼
              ┌───────────────────────────┐
              │ Python 后端（单实例）      │
              │ · TDX 7709 / MAC 连接池    │
              │ · 7615 F10 / 文件下载      │
              │ · 实时推送 / 缓存 / 搜索   │
              │ · 数据湖（Parquet + DuckDB）│
              │ · 任务：补历史、校验、导出 │
              └─────────────┬─────────────┘
                            │ TCP / HTTP
                            ▼
                  通达信行情主站 / 计算服务器
```

三条硬约束：

1. **只有 Python 后端碰行情 IO**（socket、文件、下载任务）；
2. **桌面与 Web 共用一套 `src/renderer`、`src/shared` 与设计令牌**；
3. **同一台机器只有一个后端实例**，不允许每个窗口/标签页各连一套。

## 二、现状（v0.6）与差距

### 2.1 现在长这样

```
渲染进程 Renderer（SolidJS）
   │ window.api（preload 白名单）
   ▼
主进程 Main（Node）
   │ JSON Lines（stdin/stdout）
   ▼
Python sidecar（python/tdx_bridge.py）
   │ TCP 7709
   ▼
通达信行情主站
```

- 主进程负责：窗口、轮询（`QuotePoller`）、缓存、持久化、IPC；
- Python 负责：7709 帧、握手、解析、代码表；
- 渲染层只认 `window.api`，不知道数据来自 socket。

### 2.2 差距

| 维度 | 现状 | 目标 v0.7+ |
| --- | --- | --- |
| 前端 | Electron 桌面 + Web 只读页 | 桌面 + 浏览器完整功能 |
| 数据入口 | 主进程 IPC（桌面）+ HTTP（Web） | HTTP + WebSocket |
| 行情 IO | 主进程轮询 + Python sidecar/HTTP | Python 后端统一持有 |
| 数据落地 | 只有配置 JSON | 配置 + 原始层 + Parquet 数据湖 |
| 部署 | 一个 exe | exe + Web 服务（方式待定） |
| 数据任务 | 跟着窗口生命周期 | 后端常驻，窗口关掉也能补数据 |

### 2.3 迁移路径（不推倒重来）

1. 保留现有 `python/tdx_bridge.py` 的协议与解析，加一层 HTTP/WS 门面；
   stdio 保留兼容，桌面端先双轨验证。
2. 渲染层把数据调用收敛到 `QuoteClient`：先 IPC 适配器，再 HTTP/WS 适配器。
3. Electron 改为「拉起后端 → 注入 URL → 加载同一份渲染层」。
4. 新增 Web 入口，用浏览器验证同一份界面。
5. 主进程的轮询/缓存逐步下沉；**迁移完成前只能有一个数据源**。

## 三、为什么是 Python 后端

| 问题 | 为什么不能放在渲染层/主进程 |
| --- | --- |
| 7709 是二进制 TCP | 浏览器开不了；Electron 渲染层也不该碰 |
| CORS | 浏览器不能直连行情主站 |
| 窗口节流 | 最小化时 Chromium 会节流定时器，推送节奏不能由界面决定 |
| 双前端 | 数据必须只有一份，否则桌面和 Web 会看到不同行情 |
| 长任务 | 补历史、下载、校验不能绑在某个窗口上 |
| 机器学习 | 原始报文、Parquet、DuckDB、特征生成都在 Python 生态里最顺 |

**反例**：在组件里 `setInterval(fetch(...))`；在主进程里再写一套 7709 轮询；
让每个浏览器标签页各连一次主站。

## 四、契约：类型、传输与调用边界

### 4.1 共享类型

`src/shared/` 仍是三端（桌面渲染、Web 渲染、Python 契约）的单一事实来源：

```ts
export interface Quote {
  code: string
  price: number
  // ...
}
```

- `src/shared/**` 禁止 import `electron` / `node:*` / DOM API；
- Python 侧的字段名/类型必须与 `shared` 对齐，由 fixture 测试锁住；
- 任何字段变更同时改：`shared` → Python 解析 → fixture → `docs/03`/`08`。

### 4.2 两种传输

| 模式 | 目标实现 | 用在哪 |
| --- | --- | --- |
| 请求-响应 | HTTP `POST /rpc`（或 REST） | 一次性取数：K 线、搜索、配置、下载任务 |
| 服务端推送 | WebSocket `/ws` | 高频行情、任务进度、错误事件 |

桌面端仍保留少量 **shell IPC**：窗口最小化/最大化/关闭、托盘、打开外链。
这些是「壳能力」，不是行情数据，不走 HTTP。

### 4.3 调用边界

```
组件 ──▶ stores/ ──▶ lib/quote-client.ts ──▶ 传输适配器（IPC / HTTP / WS）
```

- 组件不直接 `fetch`、不直接 `window.api`；
- `lib/ipc.ts` 只保留壳能力；
- 传输适配器由入口注入 `baseUrl` / `wsUrl`，组件代码不区分桌面/Web。

### 4.4 已实现：只读 HTTP API

`python/tdx_server.py` 用标准库 `ThreadingHTTPServer` 复用 `Bridge`：

| 能力 | 路径 |
| --- | --- |
| 健康检查 | `GET /api/ping` |
| 批量行情 | `POST /api/quotes` |
| 分类行情/排行 | `POST /api/category` |
| 成交明细 | `POST /api/trades` |
| 集合竞价 | `POST /api/auctions` |
| 资金流 | `POST /api/money_flow` |
| F10 目录/正文 | `POST /api/f10_catalog` / `api/f10_content` |
| F10 在线公告/概况/估值/财务/主营 | `POST /api/f10_announcements` / `api/f10_profile` / `api/f10_valuation` / `api/f10_finance` / `api/f10_business` / `api/f10_shareholders` / `api/f10_reports` |
| K 线/分时/五日 | `GET /api/kline` / `api/minute` / `api/five_day` |
| 代码表 | `GET /api/code_list` |
| 财务统计摘要 | `POST /api/stats_summary` |
| 统计规范化导出 | `POST /api/stats_export` |
| 统计只读查询 | `POST /api/stats_query` |
| 统计 CSV 导出 | `POST /api/stats_csv` |
| Parquet DuckDB 查询 | `POST /api/duck_query` |
| 板块/成分 | `POST /api/blocks` |
| 行业/成分 | `POST /api/industries` |
| 条件选股 | `POST /api/screen` |
| SSE 行情流 | `GET /api/stream?codes=…&interval=3000` |

- 默认绑定 `127.0.0.1:8765`，**无鉴权**，只能本机使用；
- 所有 `Bridge` 调用串行化（`TdxConnection` 非线程安全）；
- 返回 `{ok, result}` / `{ok:false, error}`，带 CORS；
- WebSocket 推送已实现（`/ws`，订阅文本帧）；Web 写操作、鉴权尚未实现。Web 端优先 WebSocket，
  失败回退 SSE，`?transport=poll` 可强制轮询。

Web 入口在 `src/web/main.tsx`：先 `window.api = createHttpApi()`，再动态导入
共享的 `src/renderer/src/main`；`vite.web.config.ts` 负责独立构建，产物 `out/web`。
桌面与 Web 共用 `src/renderer` / `src/shared`，差异只在外壳和传输适配器。

`tdx_server.py --web-dir out/web` 可把静态页与 API/SSE 放在同一端口：SPA 路由回退
`index.html`，资源带长缓存，路径穿越返回 403，支持 GET/HEAD；Web 默认用相对 `/api`。
搜索逻辑在 `src/shared/search.ts`（pinyin-pro，首次搜索懒加载），桌面与 Web 共用。

## 五、一条行情数据的旅程（目标）

```
① 后端启动
   读取主机配置 → 探活 → 握手 → 建立连接池
        ▼
② 订阅
   前端 WS 发 { type: 'subscribe', codes, interval }
        ▼
③ 实时
   0x0547 增量推送（首次基线）→ 解析 → 合并到内存快照
        ▼
④ 推送
   WS 广播 { type: 'quote', data }（按订阅主题过滤）
        ▼
⑤ 渲染
   store 更新 → 细粒度 DOM 更新 → 价格高亮
        ▼
⑥ 落盘（可选）
   原始帧/JSONL 追加到 raw 层；按批写 Parquet normalized 层
```

**现状**：桌面仍是 `QuotePoller` 每 3 秒 `fetchQuotes` + `webContents.send`；
Web 侧已有只读 HTTP API + SSE 行情流；WebSocket 推送与 Web 写操作尚未接。
迁移时保持这条链路的语义不变，换掉两端的「管道」。

### 5.1 非交易时段

- 后端按交易日历/时段降频，盘后不空转；
- 窗口关闭/Web 标签页关闭不影响后端补数据；
- 断线重连、限流退避、订阅恢复都在后端做。

## 六、状态管理：谁持有什么

| 状态 | 存放位置（目标） | 理由 |
| --- | --- | --- |
| 自选股、分组、主题、布局 | 前端 Store + 后端配置 | UI 操作要 0 延迟，落盘是副作用 |
| 行情快照 | 后端内存（权威）+ 前端 Store（展示） | 双端一致；刷新由后端控制 |
| 分时 / K 线 | 前端 `createResource` + 后端 TTL 缓存 | 生命周期跟图表走，切股票自动作废 |
| 窗口尺寸/位置 | Electron 壳 | 属于窗口，不属于数据 |
| 主机健康/探活结果 | 后端 | 只对连接层有意义 |
| 原始报文/Parquet | 数据湖 | 长期积累、可重放 |

**写入策略**：前端改状态 → 立刻更新 UI → 异步提交后端 → 防抖 + 原子写。
不允许「前端一套、后端一套」各自维护行情。

## 七、持久化

### 7.1 应用配置（现状保留）

```
%APPDATA%/StockLens/stocklens.json
{
  "version": 2,
  "state": { "groups": [...], "settings": { ... }, "activeCode": "sh600519" },
  "window": { "x": 320, "y": 180, "width": 1280, "height": 820 }
}
```

- **原子写**：先写 `.tmp` 再 `rename`，避免写一半断电；
- **版本号 + 迁移**：读旧格式、写新格式，v1→v2 已实践；
- **引用完整性**：`activeGroupId` 不存在时回落到第一个分组；
- Web 端的配置放后端（按用户/本机），不写浏览器 `localStorage` 当唯一副本。

### 7.2 数据湖（目标）

```
data/
  raw/tdx/date=YYYY-MM-DD/...          # 原始报文/JSONL，zstd，只追加
  normalized/
    bars_1d/trade_date=YYYY-MM-DD/*.parquet
    bars_1m/trade_date=YYYY-MM-DD/*.parquet
    quotes/ticks/auctions/...
    fundamentals/...
  features/                            # 派生特征，记录版本
```

硬要求见 `docs/00` 5.3 与 `PRINCIPLES.md` D6：
原始层不可变、schema 有版本、point-in-time、保留退市证券、可重放。

## 八、安全模型

| 措施 | 位置 | 作用 |
| --- | --- | --- |
| `contextIsolation: true` / `nodeIntegration: false` | Electron 壳 | 页面拿不到 Node |
| preload 白名单 | `src/preload` | 只暴露壳能力，不交 `ipcRenderer` |
| CSP | 渲染层 index.html | 限制脚本/连接来源 |
| 外链校验 | 壳 IPC | 只接受 http/https，交给系统浏览器 |
| 后端默认 `127.0.0.1` | Python 服务 | 不默认暴露公网 |
| Web 鉴权/TLS | 反向代理/服务 | 远程访问必须加，不能裸奔 |
| 主机表来源校验 | 后端 | 不自动拉远端列表，避免流量劫持 |
| 日志脱敏 | 后端 | 不记录用户公网 IP/凭据 |

## 九、目录约定

### 9.1 现状

```
src/main/        桌面壳：窗口、持久化、轮询（迁移期）、IPC
src/preload/     contextBridge 白名单
src/shared/      三端共享类型与纯函数（禁止平台 API）
src/renderer/    SolidJS 界面：components / stores / lib / styles
python/          7709 协议 + JSON Lines 服务 + 测试 + fixtures
scripts/         图标、截图、Python 入口、协议探针
```

### 9.2 目标（v0.7，落地后再改本节，不要提前按这个建目录）

```
src/main/        只留壳：窗口/托盘/更新/拉起后端
src/renderer/    桌面与 Web 共用
src/shared/      类型契约
python/          协议 + HTTP/WS 服务 + 数据任务 + 数据湖
web/             Web 入口（Vite 构建同一渲染层）
data/            运行期数据（gitignore）
```

`src/shared` 的「禁止 import 运行时 API」是硬约束：
它同时被 Node 侧和 Web 侧的 tsconfig 编译，引入平台代码必然有一侧失败。

## 十、关键取舍（ADR 摘要）

| 决定 | 取舍 | 理由 |
| --- | --- | --- |
| 双前端共用渲染层 | 不为 Web 重写一套 | 行情软件的核心是数据与交互，不是两套壳 |
| Python 后端而不是 Node | 协议/数据生态在 Python | 7709、Parquet、DuckDB、Pandas/PyTorch 都顺 |
| HTTP/WS 而不是 Electron IPC 为主 | 多一层网络 | Web 必须能连；IPC 只留给壳能力 |
| Parquet + DuckDB 而不是 SQLite | 分析型读取更顺 | 列式压缩、按分区裁剪、直接给 ML |
| 不做 7727 | 少一大块非 A 股协议 | 与 G3 一致，避免范围失控 |
| 交易不下单 | 只做行情终端 | 券商通道/合规是另一条产品线 |
