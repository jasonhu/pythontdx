# 18 · 离线数据并行同步（多进程 × 多线程 × 多服务器）

> 目标：把「全市场 × 全部数据集」的离线数据在**一个任务内**并行拉完，落盘可审计、
> 可断点续跑，并严格遵守官方要求的 **交易日 08:45–15:45 不下载** 窗口。
>
> 实现：`python/offline_sync.py`（引擎）、`python/code_archive.py`（按代码分片归档）。
> 触发：数据工具面板「并行离线同步」、HTTP `/api/offline_sync_*`、命令行
> `python offline_sync.py`。

## 1. 为什么需要独立引擎

旧「批量下载」是一条链路串行：

```text
for code in codes:
    kline(code)   # 1 条 TCP 连接，800 根一页，失败就断
```

问题不在协议，在调度：

- 单连接串行，800 根 × 5,600 只 = 上百万次 RTT，一天也跑不完；
- 失败只写进 `failed[]`，没有任务级续跑；
- `write_dataset_archive` 的「一个 dataset 一天一份」模型被误用到「每只股票一份」
  的快照数据上，第二只起直接 `skipped`，历史数据静默丢失；
- 没有交易时段保护：盘中跑全量下载会和实时行情抢官方带宽。

新引擎把工作拆成 `(dataset, code, period/date)` 任务，再拆到多个进程、每个进程
多条线程、每条线程钉在不同主站上，整体吞吐随「进程 × 线程」线性增长。

## 2. 时间窗口（硬约束）

官方在交易日 **08:45–15:45** 集中资源发行情数据，离线数据下载必须让路。

| 时间 | `offline_window().open` | 行为 |
| --- | --- | --- |
| 交易日 00:00–08:44 | `true` | 可下载；`pauseAt` = 当天 08:45 |
| 交易日 08:45–15:44 | `false` | 启动直接 `blocked`；运行中任务 `paused` |
| 交易日 15:45–23:59 | `true` | 可下载；`pauseAt` = 下一个交易日 08:45 |
| 周六/周日 | `true` | 可下载；`pauseAt` = 下周一 08:45 |
| 节假日 | 取决于 `trading_holidays.json` | 没有该文件时按工作日处理（更保守） |

- 暂停不是杀进程：worker 检查到 `pause.flag` 或本地时间进入窗口后**跑完当前任务**
  再退出，父进程把状态写成 `paused`，已完成的归档全部有效；15:45 之后重新启动，
  `skipExisting` 会跳过已完成的部分（任务级 `stat`，不联网）。
- 节假日表：`<数据目录>/trading_holidays.json`，格式
  `{"holidays": ["2026-01-01", "2026-02-16"]}`。**不提供也不会把交易日误判为
  节假日**——最多在节假日多等几小时，不会违反窗口约束。
- 显式绕过：`allow_inside_window=True`（CLI `--allow-inside-window`）只用于本地
  冒烟/测试，UI 不暴露。
- **保护不只作用于 offline_sync**：sidecar dispatch 对批量归档命令
  （`cache_klines/cache_full_klines/export_klines/archive_datasets/archive_snapshot/
  tick_archive_*/auction_archive_*/minute*/history_minute*/finance/capital/
  category/block_meta/special_limits/delisted/top_board/volume_profile/
  unusual_archive_*`）统一抛错「交易时段保护」；实时行情、K 线/分时/逐笔查询不受影响。
- **收盘自动归档窗口**随之从 15:05–15:40 改为 **15:46–16:30**：原窗口会被
  保护挡住，而且 15:40 截止会让 15:45 之后永远不触发。

## 3. 进程 / 线程 / 服务器模型

```text
父进程（tdx_bridge sidecar）
  ├─ 探活全部主站（并发 TCP 拨号，按延迟排序，剔除不可达）
  ├─ 0x044d 拉一次代码表 → 写 codes.json（worker 复用，避免每线程重复分页）
  ├─ 生成任务 → 按数据集权重贪心分片 → shards/worker-XXX.json
  ├─ subprocess 起 N 个 worker（开发态 python offline_sync.py --worker；
  │  打包态 同一个 tdx-bridge 可执行文件 --offline-worker）
  ├─ 轮询 progress/*.json，处理 pause/cancel
  └─ 全部结束后：合并 bulk parts、写 job manifest
worker（每进程）
  └─ T 条线程，每条线程一个 Bridge（独立 TCP 7709 连接）
       服务器 = servers[(workerIndex * T + threadIndex) % len(servers)]
       逐任务写 results/<worker>-<thread>.jsonl、parts/、progress/<worker>.json
```

关键设计：

- **一连接一线程**：`TdxConnection` 不是线程安全的；每条线程独占一个 `Bridge`，
  连接内部串行、连接之间并行，和 gotdx 的动态连接池是同一思路的简化实现。
- **服务器粘滞**：线程启动时钉在一台可达主站；`TdxConnection` 仍保留按
  `endpoints` 列表故障转移的能力，单站挂掉不会让线程退出。
- **不引入 `multiprocessing`**：Nuitka onefile 下 spawn 会重新解包、行为不可控；
  直接用 `subprocess` 起自己的 worker 模式，开发态与打包态共用一条代码路径。
- **重试**：任务失败先关连接重建再试一次（`retries`，默认 1）；仍失败写
  `failures/<worker>.jsonl`，不阻塞其它任务。
- **进度**：worker 每 1.5 秒原子写一次 `progress/<worker>.json`；父进程只读文件，
  HTTP 状态查询不碰网络、不阻塞。
- **状态查询插队**：sidecar 的 JSON Lines 队列是串行的，打开数据面板时
  `data_inventory` 可能正在扫几十 GB 目录。`offline_sync_status/catalog/start/cancel`
  走 `bridge.send(..., priority=true)`，插到队首，保证进度徽标立刻有状态
  （否则界面会一直显示「窗口状态未知」）。

三种落盘方式：

1. **per_code**：worker 直接调用现有 archive 方法，一只一份、互不覆盖；
2. **bulk**：worker 把行写到 `parts/<dataset>/<worker>-<thread>.jsonl.gz`，
   父进程在任务结束后合并成**每个交易日一份**的 dataset 归档
   （`finance/capital/category/block_meta/special_limits`）；
3. **单文件动作**：`server_files` 直接写原始 ZIP + 目录清单。

## 5. 按代码分片归档（修复静默丢数据）

`protocol_archive.write_dataset_archive` 是「dataset + 交易日 → 一份文件」，
同一交易日第二次调用直接 `skipped`。这对财务/涨跌停表正确，对
**每只股票一份**的分时/买卖力道/小走势是错的：历史上 `today_minute`、
`minute_aux`、`sparkline`、`recent_minute`、`history_minute` 都只保存了当天
第一只股票。

新增 `python/code_archive.py`：

```text
lake/<dataset>/trade_date=YYYY-MM-DD/
  sh600000.jsonl.gz
  sh600000.manifest.json      # schema/dataset/key/tradeDate/source/rows/sha256/files
  sz000001.jsonl.gz
  sz000001.manifest.json
```

- 已有**校验通过**的同名分片 → `skipped`，保留第一版；
- manifest 存在但数据缺失/SHA 不匹配（损坏副本）→ 允许重写；
- 写入 `.part` 后 `os.replace`；CSV 与 JSONL 同时产出；
- `list_code_archives` / `read_code_archive` / `count_code_archives` 提供列表与校验读取；
- 旧布局（整包一份）仍能列出：`_merge_archive_lists` 合并两种布局，升级后历史
  归档不会从 UI 消失；`data_integrity` 同时校验 `manifest.json` 与 `*.manifest.json`。

受影响的 bridge 方法：`minute_archive_save`、`minute_aux_archive_save`、
`sparkline_archive_save`、`recent_minute_archive_save`、`history_minute_archive_save`
及其 `*_archive_list`。HTTP 路由与 UI 不需要改签名。

## 6. 断点续跑与「不遗漏」

- 任务级：`_already_archived(task)` 只做本地 `stat`，已有文件即跳过；
- 数据集级：bulk 数据集的当日 manifest 已存在时，计划阶段整组跳过；
- **失败不合并**：bulk 数据集只要有一个任务失败就不写最终 manifest，只保留
  `parts/`。否则第二天再跑会因 manifest 已存在整组跳过，失败的那部分永远补不回来；
- 失败：逐任务记录到 `failures/*.jsonl`，manifest 保留前 500 条，UI 显示最近 6 条；
- **不覆盖**：所有归档遵守规则 12，已有且校验通过的副本不重写；
- job 目录完整保留（`job.json` / `plan.json` / `servers.json` / `logs/` /
  `results/` / `parts/` / `progress/` / `failures/` / `manifest.json`），
  事后可审计每个任务的耗时与结果。

## 7. 使用方式

> 2026-11-04 第二轮：数据工具里原「离线数据下载」与「批量下载本地数据」两个前台
> 串行入口已**删除**，只保留并行离线同步一套；F10 从所有预设移除（默认不勾选），
> 板块数据单列为 `blocks` 且默认勾选；默认并发 4 进程 × 8 线程。

数据工具面板：

1. 打开「数据工具」→「并行离线同步」；
2. 选预设（默认 `daily`）或勾选数据集；
3. 范围选「仅自选 / 全 A 股」，进程 1–12、线程/进程 1–24（默认 **4×8 = 32 条连接**）；
4. 数据源选「自动（MAC 优先）/ 仅 MAC / 仅 7709」；
5. 「开始并行同步」；顶部徽标显示窗口状态（可下载 / 保护中 + 15:45）；
6. 进度条、每 worker 进度、失败列表实时刷新（2.5 秒轮询）。

HTTP（Web/脚本）：

```bash
curl -s -X POST http://127.0.0.1:7615/api/offline_sync_catalog -d '{}'
curl -s -X POST http://127.0.0.1:7615/api/offline_sync_start \
  -H 'Content-Type: application/json' \
  -d '{"preset":"daily","scope":"all","processes":3,"threads":4}'
curl -s -X POST http://127.0.0.1:7615/api/offline_sync_status -d '{}'
curl -s -X POST http://127.0.0.1:7615/api/offline_sync_cancel -d '{}'
```

命令行（开发/运维）：

```bash
cd python
python offline_sync.py --preset daily --scope all --processes 3 --threads 4
python offline_sync.py --datasets kline --periods day,1m --scope codes \
  --codes sh600519,sz000001 --force --allow-inside-window
python offline_sync.py --datasets ticks --dates 2026-11-03 --scope watchlist ...
```

退出码：`0` 完成/暂停，`2` 窗口保护被拒，`1` 失败。

## 9. 边界

- 只做 A 股 + 通达信；7727/EX、港股美股期货不做。
- `ticks`/`history_minute` 全市场是**天量**（单日可达数十 GB），默认只对自选，
  全市场需要显式选择并确认磁盘空间。
- `f10` 的 `full` 档每只约 30 次 7615 请求，全市场首次建库耗时以小时计；
  默认 `core`（12 个分区）。
- 7615 没有公开的并发/限流文档，线程数过大可能被限流；失败会记录并在下次续跑。
- 退市代码不在当前代码表里，`delisted` 数据集必须显式提供代码。
- `volume_profile`（0x051a）在免费主站全部超时，**不进任何预设**；勾选后每个任务会
  等 8 秒超时并记失败，只适合在确认节点可用时手动验证。
- 节假日表缺省只按周末判断：节假日会被当成交易日，窗口内同样禁止下载
  （更保守，不会误放）；需要精确判断时在数据目录放 `trading_holidays.json`。
