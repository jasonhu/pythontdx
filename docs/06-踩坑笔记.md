# 06 · 踩坑笔记

> 这里记录的都是**本项目真实踩到并解决**的问题，不是从搜索引擎抄来的清单。
> 每一条都包含「现象 → 原因 → 解决」，方便以后回查。

---

## 1. PowerShell 里 `npm` 报「running scripts is disabled」

**现象**

```
npm : File C:\Program Files\nodejs\npm.ps1 cannot be loaded because
running scripts is disabled on this system.
```

**原因**
Windows PowerShell 默认执行策略是 `Restricted`。在 PowerShell 里输入 `npm` 时，
解析到的其实是 `npm.ps1`（而不是 `npm.cmd`），于是被执行策略拦下。

**解决**

```powershell
npm.cmd install                            # 方案 A：绕过 .ps1
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned   # 方案 B：一劳永逸
```

## 2. Electron 装好了，但没有 `electron.exe`

**现象**
`npm install` 成功，但 `node_modules/electron/dist/` 不存在，运行时报
`Electron failed to install correctly`。

**原因**
**Electron 44 已经取消了 `postinstall` 脚本**，改成「第一次被 `require` 时惰性下载」。
所以 `npm install` 之后看不到二进制是正常的，它会在第一次 `npm run dev` 时才去下载。
（顺带一提：新版 npm 默认还会拦截依赖的 install scripts，esbuild 之类的包也会被拦，
但 esbuild 的平台二进制是通过 optionalDependencies 装的，通常不受影响。）

**解决**

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_CUSTOM_DIR = '{{ version }}'
node node_modules/electron/install.js
```

其中国内网络下 **`ELECTRON_MIRROR` 是必须的**（GitHub Releases 基本不可达），
而 `ELECTRON_CUSTOM_DIR={{ version }}` 也是必须的——npmmirror 的目录结构是
`/44.4.3/`，不是 GitHub 的 `/v44.4.3/`。

项目已经把这两项写进 `.npmrc`，npm 会把它们注入成 `npm_config_*` 环境变量传给子进程，
所以正常 `npm install` 就能自动走镜像。

**验证镜像配置是否生效**：

```powershell
npm run env | Select-String electron
# npm_config_electron_custom_dir={{ version }}
# npm_config_electron_mirror=https://npmmirror.com/mirrors/electron/
```

## 3. 分时接口 `JSON.parse` 失败

**现象**
实时行情正常，但分时图一直报「行情接口返回了非预期的数据格式」。

**原因**
我画蛇添足地给 URL 加了个 `&_var=min_data_sh600519` 参数用来「防缓存」。
**腾讯的 JSON 接口只要看到 `_var`，就会返回 JSONP**：

```
var min_data_sh600519={"code":0,"data":{...}};
```

这已经不是合法 JSON 了。

**解决**
去掉 `_var` 参数即可。缓存交给自己的 TTL 缓存层去做，不要动上游的参数。

## 4. Solid 的 `createResource` 因为 source 身份变化而反复请求

**现象**
主进程每 3 秒推一帧行情，图表却也跟着每 3 秒重新拉一次数据。

**原因**
`createResource` 内部把 source 包成了 `createMemo(source)`（见 `solid.cjs`）。
读 `props.code` 会订阅父组件传下来的响应式 getter，
而父组件每 3 秒就会产生一个新的 quote 对象——虽然 `.code` 字符串没变，
但 source 每次返回的都是**新的对象字面量**，引用不等，于是每次都被判定为「变化了」。

**解决**
用 `createMemo` 把原始值稳定下来（memo 默认做值比较）：

```ts
const code = createMemo(() => props.code)   // 字符串没变 → 不向下游传播
// ...
createResource(() => ({ code: code(), tab: tab(), ... }), fetcher)
```

**验证方式**：在 source 里打日志，正常情况应该只有「挂载时 1 次 + 定时刷新 N 次」。
我们当时看到的是 6 次（每一次行情推送都触发），加上日志后立刻定位。

## 5. Solid 1.9 的 `createResource` 返回值变了

**现象**

```
error TS2339: Property 'refetch' does not exist on type 'Resource<ChartData>'.
```

**原因**
Solid 1.9 的类型定义是：

```ts
export type ResourceReturn<T, R> = [Resource<T>, ResourceActions<T | undefined, R>]
export type ResourceActions<T, R> = { mutate: Setter<T>; refetch: (info?: R) => ... }
```

`refetch` / `mutate` 在**元组的第二个元素**上，不在 resource 本身。

**解决**

```ts
const [data, { refetch }] = createResource(source, fetcher)
```

**附带发现**：resource 处于 `errored` 状态时，**直接调用 `data()` 会抛出异常**
（`if (err !== undefined && !pr) throw err`）。
所以读取前要先判 `data.error`，或者在 `<Show when={!data.error}>` 的 fallback 里避开读取。

## 6. Solid JSX 里的 SVG 属性必须用 kebab-case

**现象**

```
error TS2322: Property 'strokeWidth' does not exist on type 'SvgSVGAttributes<SVGSVGElement>'.
Did you mean '"stroke-width"'?
```

**原因**
React 用的是驼峰（`strokeWidth`），但 Solid 直接映射到真实 DOM/SVG 属性，用的是
kebab-case（`stroke-width`）。

**解决**
统一写 `'stroke-width'`。本项目还顺手把它收进了一个 `svgProps()` 工厂函数，
让所有图标共享同一套规格，个别图标想调细描边只需传第二个参数。

## 7. `ResizeObserver loop completed with undelivered notifications`

**现象**
控制台反复出现这条告警。

**原因**
`ResizeObserver` 的回调里写信号 → 触发重绘 → 尺寸再次变化 → 又触发回调。
虽然浏览器会自动容错（不会真的死循环），但告警很吵。

**解决**
在回调里做**值比较**，尺寸真的变了才写信号：

```ts
setSize((prev) => (prev.width === w && prev.height === h ? prev : { width: w, height: h }))
```

## 8. 港股的字段布局和 A 股完全不同

**现象**
把 A 股的解析逻辑直接套到港股上，市净率位置显示的是 `TENCENT`，涨停价位置显示的是 52 周高点。

**原因**
A 股响应有 **88** 个字段，港股只有 **78** 个，而且从下标 30 往后含义就分叉了：
港股下标 30 是 `2026/09/21 16:08:36`（带斜杠），A 股是 `20260921161437`（纯数字）；
港股 46 是英文名、48/49 是 52 周高低。

**解决**
按市场分派到两个解析函数（`buildAShareQuote` / `buildHkQuote`），
拿不到含义的字段一律置 `undefined`，界面用统一的 `—` 占位。
时间解析也要同时兼容两种格式，并统一按东八区换算成时间戳。

**额外注意**：港股成交量单位是**股**，A 股是**手**；
成交额 A 股字段 37 是**万元**，港股是**元**。

## 9. 接口失败会引发重试风暴

**现象**
分时接口报错的那次调试里，日志里短时间内出现了大量重复的 `trend:minute` 请求。

**原因**
上游失败 → 渲染层重新求值 → 再次 invoke → 主进程再打一次上游。
因为失败结果不进缓存，每一次都会真的发出网络请求。

**解决**
在缓存层做 **同 key 并发请求合并**：把在途的 Promise 也存起来，
同一时刻同一个 key 最多只有一个真实请求，无论上游并发调用多少次。
失败时**不写缓存**，但一定要清掉在途标记，否则后续请求会被永久挂住。

```ts
const inFlight = this.pending.get(key)
if (inFlight) return inFlight
```

这是本项目里「防御性设计」价值最高的一个改动。

## 10. 无边框窗口的按钮点不动

**现象**
自绘标题栏做完，窗口能拖动，但最小化/关闭按钮点不动。

**原因**
`-webkit-app-region: drag` 会把整个区域变成「窗口拖拽热区」，
Chromium 不再把鼠标事件派发给里面的元素。

**解决**
给所有交互元素显式声明：

```css
.titlebar__actions,
.win-controls,
.search-wrap {
  -webkit-app-region: no-drag;
}
```

**排查技巧**：如果某个按钮「看起来能 hover 但点击无反应」，
先怀疑它的祖先里有 `drag` 区域。

## 11. 类型检查通过了，但退出码是 1

**现象**
`npm run typecheck` 没有任何 `error TS` 输出，但 `$LASTEXITCODE` 是 1。

**原因**
是我在验证时把它管道给了 `Select-String`，管道里最后一个命令的退出码覆盖了 npm 的。
**不是代码问题**——单独执行时退出码是 0。

**教训**：判断「命令是否成功」时，别把原生命令接进 PowerShell 管道，
要么先执行再单独 `echo $LASTEXITCODE`，要么看有没有具体的 `error TS` 行。

## 12. `.npmrc` 里的自定义键会被 npm 警告

**现象**

```
npm warn Unknown project config "electron_mirror".
```

**原因**
`electron_mirror` 不是 npm 自己的配置项，npm 不认识所以给个提示。

**结论**：**这是完全正常的**，这些键的作用就是被转成 `npm_config_*` 环境变量喂给
Electron 的下载器。警告可以忽略，功能不受影响。
