# 03 · 通达信行情手册（7709 协议 + Python 桥接）

> 核对时间：2026-10 · 样例：`sh600519`（贵州茅台）、`sh000001`（上证指数）。
> 协议来源：社区逆向实现 [pytdx](https://github.com/rainx/pytdx)、[eltdx](https://github.com/electkismet/eltdx)，
> 以及本项目 2026-10-29 收盘后的实盘抓包。**不是通达信官方 API。**

---

## 一、为什么是 Python sidecar

行情层是一个独立进程 `python/tdx_bridge.py`：

```
渲染层 ── IPC ──▶ 主进程 services/tdx/index.ts
                          │  JSON Lines（stdin/stdout）
                          ▼
                 Python 子进程 tdx_bridge.py
                          │  TCP 7709
                          ▼
                    通达信行情主站
```

分工：

| 层 | 负责 |
| --- | --- |
| Python | TCP、握手、帧、zlib、变长整数、压缩浮点、字段解析、财务合并 |
| 主进程 TS | 拉起/重启子进程、请求排队、超时、TTL 缓存、代码表 + 拼音搜索 |
| 渲染层 | 只跟 `window.api` 打交道，不知道数据来自 socket 还是 HTTP |

打包时 PyInstaller 把脚本打成单文件，放在 `resources/tdx-bridge/`；
用户机器不需要安装 Python。开发模式则直接 `python3 python/tdx_bridge.py`。

> **v0.7 目标**：sidecar 升级为 Python 后端服务（HTTP/WS），
> 桌面与 Web 共用；协议层、帧格式、解析函数不变，只是把「stdin/stdout」换成
> 「HTTP 请求 + WebSocket 推送」。迁移细节见 `PLAN.md` P0。

## 二、连接与帧

### 2.1 主站

TCP **7709**，多个主站按顺序 failover。当前 `python/tdx_bridge.py` 的
`ENDPOINTS` 里有 5 个**临时种子**（124.71.187.122 / 180.153.18.170 /
116.205.183.150 / 111.230.186.52 / 119.97.185.59），2026-10-30 实盘请求成功，
但**没有逐台测速，也不是「最新列表」**。

目标策略（`docs/08` 第三节、`PLAN.md` TD21）：

1. 优先读本机通达信客户端 `connect.cfg` 的官方主机表；
2. 其次用带日期的种子列表，启动时用**真实业务命令**并发探活；
3. 用户配置可覆盖；写坏要报错，不静默回退；
4. 不自动拉取远端主机表，避免供应链风险。

主站会变，连不上时先看探活记录，不要再往代码里加一个「看起来能 ping 通」的 IP。

### 2.2 握手

**只发一条 `0x000d`，data = `[0x01]`。**

这是本项目踩到的最大的坑：pytdx 的 `setup1 / setup2 / setup3` 三连包会让服务端
进入旧版会话，之后 `0x053e` 只回 4 字节空包（`01 05 00 00`），看起来像「没有行情」。
改成只发一条握手后，五档、K 线、分时全部正常。

### 2.3 请求帧

12 字节头 + data：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 1 | 固定 `0x0c` |
| 1 | 4 | msgId，u32 LE；服务端原样回显，任意非零值即可 |
| 5 | 1 | control，固定 `0x01` |
| 6 | 2 | `data.length + 2`，u16 LE |
| 8 | 2 | 同上（协议要求写两遍） |
| 10 | 2 | 命令号，u16 LE |
| 12 | n | data |

### 2.4 响应帧

16 字节头 + body：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | 固定 `b1 cb 74 00` |
| 4 | 1 | control |
| 5 | 4 | msgId（服务端回显，可能和请求不同） |
| 9 | 1 | 保留 |
| 10 | 2 | 命令号 |
| 12 | 2 | `zipLength` |
| 14 | 2 | `length` |

- 先读 16 字节，再读 `zipLength` 字节；
- `zipLength == length` → 不压缩；否则对 body 做 `zlib.decompress`；
- 每次请求都有 8 秒超时；超时直接销毁连接，下一次请求重连，避免报文错位。

## 三、命令与字段

### 3.1 批量五档 `0x053e`

请求 data：

```
8 字节前缀 [5,0,0,0,0,0,0,0]
u16 数量
每条 7 字节：u8 市场（0 深 / 1 沪 / 2 京）+ 6 字节 ASCII 代码
```

**单次最多 80 只**。实测 81 只和 100 只都只返回 80 条，是静默截断，不会报错。

响应：

```
2 字节头
u16 数量
记录 × N
```

每条记录（变长）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| market | u8 | 0/1/2 |
| code | 6s | ASCII |
| active1 | u16 | 状态原始值 |
| price | varint | 现价，单位 0.01 |
| lastCloseDiff | varint | 现价 + 它 = 昨收 |
| openDiff / highDiff / lowDiff | varint | 相对现价的差分 |
| serverTimeRaw | varint | 时间原始值；**语义未确认**，本项目暂用接收时间 |
| unknown | varint | 时间后的保留字段 |
| totalHand | varint | 总成交量，单位「手」 |
| currentHand | varint | 现手 |
| amount | u32 | 压缩浮点，单位「元」 |
| inside / outer | varint | 内盘 / 外盘 |
| unknown ×2 | varint | 保留 |
| 5 × (bidDelta, askDelta, bidVol, askVol) | varint | 五档，价格 = 现价 + delta |
| tradingStatus | u16 | 交易状态 |
| 4 × tailMetric | varint | 尾部指标 |
| riseSpeed / active2 | i16 + u16 | **可选 4 字节**，部分响应没有 |

价格缩放：`price = raw / (100 × divisor)`，`divisor` 来自代码表的 `decimal`：
`decimal ≤ 2 → 1`，`decimal = 3 → 10`。

**指数的坑**：`sh000001` 的价格字段有效，但五档字段是垃圾值（实测买一价能到 41 万）。
解析时按代码规则识别指数，直接把 `bids` / `asks` 置空。

### 3.2 K 线 `0x052d`

请求 data（42 字节）：

```
u16 市场 + 6 字节代码
u16 周期（4 日 / 5 周 / 6 月）
u16 1
u16 start（0 = 最新）
u16 count（1..800）
u16 adjust（0 不复权 / 1 前复权 / 2 后复权）
u32 锚点（0）
20 字节 0
```

响应：

```
u16 数量
每条：
  u32 日期 YYYYMMDD
  varint openDiff / closeDiff / highDiff / lowDiff
  u32 volume（压缩浮点，股）
  u32 amount（压缩浮点，元）
  指数额外 4 字节：上涨家数 u16 + 下跌家数 u16
```

价格是**差分编码**：`open = base + openDiff`，`close = openRaw + closeDiff`，
`base` 从 0 开始，下一根的 base = 本根 close。价格单位 0.001 元。

- `adjust=1` 是服务端前复权；实测 600519 最近 5 根与腾讯 qfq 逐根一致。
- 成交量 `wire / 100` 得「手」；可转债不再除。
- **指数每条记录多 4 字节**，不跳过会把下一根的日期读歪。

### 3.3 当日分时 `0x0537`

请求 data：`u16 市场 + 6 字节代码 + 00 00 00 93`。

响应：`u16 数量 + u16 保留 + 每条 (priceField, avgField, volume)`，全部 varint。

- 第 0 条是绝对值，之后是相对第 0 条的增量；
- 价格 `/ (100 × divisor)`，均价 `/ (10000 × divisor)`；
- 240 个点，时间不是字段，按序号推：0=09:31，119=11:30，120=13:01，239=15:00；
- **没有日期、没有昨收**，由调用方用不复权日 K 的最后两根补。

### 3.4 历史分时 `0x0fb4`

请求 data：`u32 日期 YYYYMMDD + u8 市场 + 6 字节代码`。

响应：`u16 数量 + f32 昨收 + 每条 (priceDelta, auxDelta, volume)`。

- 价格从 0 开始累加；
- 昨收直接来自响应头，适合五日分时；
- 没有均价字段，本项目用「分钟价 × 量的 VWAP」近似。

### 3.5 代码表 `0x044d` / 数量 `0x044e`

数量请求：`u16 市场 + u32 客户端日期` → `u16 数量`。

代码表请求：`u16 市场 + u32 start + u32 limit + 4 字节 0`，单页最多 1600。

代码表记录定长 37 字节：

| 偏移 | 字段 |
| --- | --- |
| 0 | 代码 6s |
| 6 | multiple u16 |
| 8 | 名称 GBK 16s |
| 24 | 未知 f32 |
| 28 | decimal u8 |
| 29 | 昨收 f32 |
| 33 | 未知 4s |

全量 3 个市场约 5.2 万条，实测 0.75~0.86 秒。名称会用空格做视觉对齐
（`五 粮 液`），必须去掉；英文名只把连续空格压成一个。

### 3.6 财务 `0x0010`

请求 data：`u16 数量 + 每条 (u8 市场 + 6 字节代码)`，单次最多 80。

响应：`u16 数量 + 每条 143 字节`，其中代码 7 字节后是 136 字节财务结构：

| 结构偏移 | 字段 | 单位 |
| --- | --- | --- |
| 0 | 流通股本 f32 | 万股 |
| 16 | 总股本 f32 | 万股 |
| 40 | EPS f32 | 元/股（报告期口径，不是 TTM） |
| 128 | 每股净资产 f32 | 元/股 |

用途：流通市值、总市值、换手率、市净率。
**PE TTM / 量比 / 涨跌停价暂不提供**——EPS 是报告期口径，直接算 PE 会和行情软件的
TTM 差很多；界面这几项显示「—」。

### 3.7 批量快照 `0x054c`

请求 data 与 `0x053e` 相同：`8 字节前缀 05 00... + u16 数量 + 每条 (u8 市场 + 6 字节代码)`，
单次最多 80 只。

响应：`u16 头 + u16 数量`（数量在 `[2:4]`），记录从偏移 4 开始，**长度可变**，
按「市场 + 6 位代码」标记切分。单条记录：

| 偏移 | 字段 |
| --- | --- |
| 0 | 市场 u8 |
| 1 | 代码 6s |
| 7 | active u16 |
| 9 | 五个差分 varint：current / last_close / open / high / low |
| — | 时间 varint、时间后未知 varint |
| — | 总手 varint、现手 varint |
| — | 成交额 u32（压缩浮点） |
| — | 内盘 / 外盘 / 外盘后未知 / 开盘金额（各 varint） |
| — | 买一价差 / 卖一价差 / 买一量 / 卖一量（各 varint） |
| — | 56 字节尾部保留区 |

价格：`current_milli = current_delta * 10`，实际价 = `milli / 1000 / divisor`
（A 股 divisor=1，即 `current_delta / 100`）；买一/卖一价 = `(current_milli + delta*10)` 再除。
盘口**只稳定返回买一/卖一**，不要把它当五档用。

fixture：`python/fixtures/snapshot2.hex`（2026-10-30 实盘，600519 + 000858）。

### 3.8 增量刷新 `0x0547`

请求 data：`u16 数量 + 每条 (u8 市场 + 6 字节代码 + u32 游标)`，单次最多 **100** 只；
首次游标传 0。响应不是明文：**每个字节 XOR 0x93**，解码后 `u16 数量` 在偏移 0，
记录从偏移 2 开始，按「市场 + 代码」标记切分。

单条记录：

| 偏移 | 字段 |
| --- | --- |
| 0 | 市场 u8 |
| 1 | 代码 6s |
| 7 | active u16 |
| 9 | 五个差分 varint（同 `0x054c`） |
| — | 更新时间 u32 |
| — | 状态 varint、总手 varint、现手 varint |
| — | 成交额 u32（压缩浮点） |
| — | 内盘 / 外盘 / 外盘后未知 / 开盘金额（各 varint） |
| — | 五档：买价差 / 卖价差 / 买量 / 卖量（各 varint，循环 5 次） |
| — | 尾部保留区 |

首次刷新返回五档基线；后续调用才体现增量。当前实现的是**单次刷新**，
推送队列（主站主动下发、`msgId=0` 的未配对帧）尚未接入，见 `docs/09` P1。

fixture：`python/fixtures/refresh2.hex`（2026-10-30 实盘，600519 + 000858）。

### 3.9 分类行情 `0x054b`

请求 data 是 **9 个 u16**：

```text
category, sort_type, start, count, sort_reverse, 5, filter_raw, 1, 0
```

- `category=6` 是沪深 A 股；`sort_type` 常用 `0x000e`（涨幅）、`0x000a`（成交额）、
  `0x0006`（现价）；`sort_reverse=1` 降序、`2` 升序。
- 一页最多 80 条；`start` 翻页。服务端排序，不要本地重排。

响应：`u16 头 + u16 数量`（数量在 `[2:4]`），记录从偏移 4 开始**连续排列**，
单条由「9 字节头 + 变长字段 + 56 字节尾」组成。前段字段与 `0x053e` 类似：

| 偏移 | 字段 |
| --- | --- |
| 0 | 市场 u8 |
| 1 | 代码 6s |
| 7 | active1 u16 |
| 9 | 五个差分 varint：current / last_close / open / high / low |
| — | 时间 varint、负现价口径 varint |
| — | 总手 / 现手 varint |
| — | 成交额 u32（压缩浮点） |
| — | 内盘 / 外盘 / 外盘后 / 开盘金额（各 varint） |
| — | 买一价差 / 卖一价差 / 买一量 / 卖一量（各 varint） |
| — | 56 字节尾 |

56 字节尾里已确认的字段：

| 尾偏移 | 字段 |
| --- | --- |
| 0 | status/sort u16 |
| 2 | 涨速 i16（/100） |
| 4 | 短周期换手 i16（/100） |
| 6 | 近 2 分钟金额 f32 |
| 10 | 开盘抢筹 i16（/100） |
| 22 | 量增速 f32 |
| 26 | 盘口深度 f32 |
| 54 | active2 u16 |

价格与 `0x053e` 同口径：`raw / 100 / divisor`；`lockedAmount = 买一价 × 买一量 × 100`。
限价涨停时卖一为空是正常情况，不能当解析失败。

fixture：`python/fixtures/category5.hex`（2026-10-30 实盘，涨幅榜前 5）。

### 3.10 成交明细 `0x0fc5` / `0x0fc6`

当日用 `0x0fc5`，历史用 `0x0fc6`；单页上限 1800 条。

| 命令 | 请求 data |
| --- | --- |
| `0x0fc5` | `u8 市场 + u8 0 + 6s 代码 + u16 start + u16 count` |
| `0x0fc6` | `u32 YYYYMMDD + u16 市场 + 6s 代码 + u16 start + u16 count` |

响应：

- `0x0fc5`：`u16 数量 + 记录`（记录从偏移 2 开始）。
- `0x0fc6`：`u16 数量 + f32 价格基数 + 记录`（记录从偏移 6 开始）。
  价格基数只做保留，价格仍按差分累计。
- 单条记录：`u16 当日分钟数` + varint 价格差分、成交量、笔数、状态、尾部字段。
  价格是**累计值**：A 股 `/100`，可转债 `/1000`。

状态：`0` 买、`1` 卖、`2` 中性、`5` 盘后固定价格、`8` 集合竞价快照。
`status=8` 不是真实成交，不能算成交额；09:25 且非 8 是开盘撮合。

fixture：`python/fixtures/trades-today.hex`（600519 当日 20 条）、
`python/fixtures/trades-history.hex`（600519 2026-10-28 盘后 5 条）。

> **已知边界**：2026-10-29 对 `0x0fc6` 返回过不符合上述布局的 payload
> （疑似当日历史数据未就绪/主站异常）。解析器应报错，不能按 `0x0fc5` 格式硬解；
> 重试或换一个已收盘的历史日期。此结论待更多日期样本复核。

### 3.11 集合竞价 `0x056a`

请求固定 28 字节：

```text
u8 市场 + u8 0 + 6s 代码 + u32 日期 + u32 selector + u32 0 + u32 start + u32 limit
```

- 日期 `0` 表示当日；`YYYYMMDD` 表示历史。
- selector 默认 `3`，limit 默认 `500`，start 默认 `0`。

响应：`u16 数量 + 数量 × 16 字节`，每条记录：

| 偏移 | 字段 |
| --- | --- |
| 0 | 当日分钟 u16 |
| 2 | 价格 f32（已经是元，不再差分） |
| 6 | 虚拟匹配量 u32（手） |
| 10 | 未匹配量 i32（带符号；取绝对值 + 方向） |
| 14 | 保留 u8 |
| 15 | 秒 u8 |

时间 = `HH:MM:SS`。**虚拟匹配量不是已经发生的成交**，不能当逐笔成交额；
09:25 的过程快照也不能替代正式撮合。

fixture：`python/fixtures/auction-today.hex`（600519 2026-10-30，50 点）。
历史请求（日期非 0）已构造并得到过空页；**非空历史样本尚未验证**。

### 3.12 服务器文件读取 `0x06b9`

请求固定 **308 字节**：

```text
u32 offset + u32 size + 300 字节路径（ASCII，NUL 填充，反斜杠转 /）
```

- 单块 `size` 范围 `1..60000`，默认 30000。
- 响应：`u32 实际长度 + 内容 + 可选 trailing`。
- `实际长度 < size` 视为最后一块；如果文件长度恰好是 size 的整数倍，
  需要再请求一次空块才能确认结束。

fixture：`python/fixtures/file-zhb-head.hex`（`zhb.zip` 前 64 字节，
`504b0304` ZIP 文件头）。

完整下载由上层循环 `offset += chunkLen`，直到短块或空块；项目默认保存到
`~/.local/share/stocklens/data/raw/tdx/<文件名>`（可用 `STOCKLENS_DATA_DIR` 覆盖）。
`tdx_stats` 会下载 `zhb.zip` 并解析其中的 `tdxstat.cfg` / `tdxstat2.cfg`：

- 2026-10-30 实测：1,343,764 字节、45 块、47 个 ZIP 条目；
- 两份 CFG 各 8,103 条有效行，主日期 `20261029`；
- 摘要返回前 3 行样本；原始 ZIP 与 SHA256 落盘。

完整下载/`tdxstat.cfg` 解析已接入；盘后行情文件入库尚未做。

`tdx_stats_export` 会额外写规范化层：

```text
normalized/tdx/zhb_stats/
  manifest.json
  stats.db
  trade_date=YYYYMMDD/tdxstat.jsonl.gz
  trade_date=YYYYMMDD/tdxstat2.jsonl.gz
```

- 按行内 `statsDate` 分区，`manifest.json` 记录源 SHA256、解析器版本、分区计数、
  生成时间和跳过的空日期行数；
- 2026-10-30 实测：8100 行有效，主分区 20261029 有 8048 行；
  3 行空日期被跳过并显式计数；另有 15 个单行旧日期分区，保留原样；
- `stats.db` 是标准库 SQLite 查询层（1.7 MB）：
  - `tdxstat(stats_date, market, code, beta60, pe_ttm, free_float_shares_10k, …)`
  - `tdxstat2(stats_date, market, code, amount_10k, seal_amount_10k, …)`
  - `meta(schema_version, parser, source_sha256, generated_at, stat_count)`
  - 代码索引；可直接 `SELECT … WHERE code=? ORDER BY stats_date DESC`；
  - `stats_query` 在只读连接上执行单条 SELECT/WITH，最多 500 行；
  - `stats_csv` 把两张表全量导出到 `csv/tdxstat.csv` / `tdxstat2.csv`（UTF-8 BOM）；
- 这是 **JSONL.gz + SQLite 暂存层**，Parquet + DuckDB 尚未接入。

### 3.12.1 板块文件 `block_*.dat`

板块文件通过 `0x06b9` 下载（与 `zhb.zip` 同一条文件通道）：

| 文件 | 类型 | 2026-10-30 实测 |
| --- | --- | --- |
| `block_gn.dat` | 概念 | 757,083 B，269 块，41,364 个成分代码 |
| `block_zs.dat` | 指数 | 329,507 B，117 块，11,554 个成分代码 |
| `block_fg.dat` | 风格 | 161 块，20,092 个成分代码 |
| `block.dat` | 一般 | 100 块，16,851 个成分代码 |

格式：

```text
384 字节头（前 64 字节 "Registry ver:1.0 ..."）
u16 count
count × 2813 字节记录：
  9s   板块名（GBK，\0 填充）
  u16  股票数
  u16  类型
  2800s 代码区，每只 7 字节（6 位 ASCII + \0）
```

- 记录按时间顺序排列，`count` 必须与文件长度匹配，截断直接报错；
- 代码区里没有市场前缀，解析时需要查 `0x044d` 代码表补 `sh/sz/bj`；
- `000001` 在“精选指数”里是上证指数，在“沪深300”里是平安银行：
  含“指数”的板块优先匹配 `ZS`，其余优先匹配 `GP-A`；
- fixture：`python/fixtures/block-gn-head.hex`（1 条真实记录，88 只）；
- 只做板块列表 + 成分股；板块指数行情、板块 K 线尚未接。

### 3.12.2 行业分类 `tdxhy.cfg` + `incon.dat`

`tdxhy.cfg` 通过 `0x06b9` 下载（150,556 B），每行：

```text
market|symbol|TDX行业代码|…|TDXRSHY代码
0|000001|T1001|||X500102
```

- 第 3 段是通达信行业代码（如 `T1001` 银行）；
- 第 6 段是通达信二级行业（如 `X500102` 股份制银行）；
- 行业名称来自 `zhb.zip` 内的 `incon.dat`：
  - `#TDXNHY` 段：`T01|能源`、`T1001|银行`；
  - `#TDXRSHY` 段：`X500102|股份制银行`；
- 2026-10-30 实测：111 个行业、5,587 只股票；
- 解析后按 `T` 代码分组，代码同样用 `0x044d` 补市场前缀；
- 当前只展示通达信行业（`T`），`X` 二级行业保留在原始行的 `rsCode` 里，
  尚未做二级行业切换。

### 3.13 资金流向 `0x0ffc`

请求 38 字节：`u8 市场 + u8 0 + 6s 代码 + 28 字节 0`。
这条命令的 `msg_id` 不是普通序号：低 8 位保留序号，高字节带
`channel=0x2d`、`route=0x7e`，否则主站会返回空数据或错误结果。

响应：`0x28 头 + 0x58 记录`；头里市场 u8、代码 `[2:8]`、数量 `[0x26:0x28]`。
每条记录：

| 偏移 | 字段 |
| --- | --- |
| 0 | 日期 u32（YYYYMMDD） |
| 4 | 21 个 u32 原始字段 |
| 8 | 成交额 f32（`raw[1]`） |
| 10 个 u32 起 | 8 组买/卖 u16，展开成 16 个 buckets |

派生公式（与服务端一致）：

```text
main_net = (b0-b1 + b4-b5) / 50000 * total_amount
main_ratio = (b0-b1 + b4-b5) / 500
main_buy_net = (b2-b3 + b6-b7 + b10-b11 + b14-b15) / 50000 * total_amount
```

**节点差异**：普通行情节点可能只返回日期、金额全 0；必须走资金流专用节点
（`python/tdx_bridge.py` 的 `MONEY_FLOW_HOSTS`），并对全 0 结果报错而不是展示 0。
接口固定返回最近 5 个交易日，不能通过参数取更长历史。

fixture：`python/fixtures/money-flow-5.hex`（600519 最近 5 日；10-30 主力净额
1.43 亿、占比 5.088%）。右侧栏资金流页签已接，四档明细未展开。

### 3.14 F10 公司资料 `0x02cf` / `0x02d0`

目录 `0x02cf`：

- 请求 12 字节：`u16 市场 + 6s 代码 + 4 字节 0`。
- 响应：`u16 数量 + N × 152 字节`；
  每条 = 64 名称 + 80 文件名 + u32 起始偏移 + u32 长度，名称/文件名 GBK。

正文 `0x02d0`：

- 请求 102 字节：`u16 市场 + 6s 代码 + u16 0 + 80 字节文件名 + u32 offset + u32 length + u32 0`。
- 响应：12 字节头 + GBK 正文；正文长度在头 `[10:12]`。
- 文件名/偏移/长度必须原样使用 `0x02cf` 返回的值，不要猜。

fixture：`python/fixtures/f10-cat2.hex`（前两段：最新提示、公司概况）、
`f10-content200.hex`（最新提示前 200 字节）。600519 实盘目录共 16 段；
UI 已提供 F10 弹窗（左目录、右正文，按段缓存）。

> `0x053e`、`0x0547`、`0x054c`、`0x054b`、`0x0fc5/0x0fc6`、`0x056a`、`0x06b9`、`0x0ffc`、
> `0x02cf/0x02d0` 的二进制布局不同，解析器不能互换；UI 主链路已切到 `0x0547`，
> `0x054c` 用于批量快照，`0x054b` 用于排行/分类，`0x0fc5/0x0fc6` 用于逐笔，
> `0x056a` 用于竞价过程，`0x06b9` 用于服务器文件，`0x0ffc` 用于资金流，
> `0x02cf/0x02d0` 用于 F10 文本，`0x053e` 保留兼容与差分。

## 四、JSON Lines 桥接协议

Python 进程从 stdin 读一行 JSON，向 stdout 写一行 JSON；stderr 只放日志。

请求：

```json
{ "id": 1, "cmd": "quotes", "payload": { "codes": ["sh600519"] } }
```

成功：

```json
{ "id": 1, "ok": true, "result": [ ... ] }
```

失败：

```json
{ "id": 1, "ok": false, "error": "行情服务器连接失败，请检查网络" }
```

命令表：

| cmd | payload | result |
| --- | --- | --- |
| `ping` | — | `"pong"` |
| `code_list` | — | 全量代码表 |
| `quotes` | `{ codes }` | `Quote[]`（`0x053e`，五档兼容） |
| `snapshots` | `{ codes }` | `Quote[]`（`0x054c`，买一/卖一） |
| `refresh` | `{ codes, cursors? }` | `Quote[]`（`0x0547`，五档基线） |

## 六、稳定性与边界

| 风险 | 对策 |
| --- | --- |
| 主站改名/下线 | 多主站 failover；列表集中在 `ENDPOINTS` |
| 握手方式变化 | 只发 0x000d；出现空包先检查这里 |
| 单次 80 只截断 | 按 80 分批；Python 与 TS 两侧都有常量 |
| 报文错位 | 每次请求独立超时，超时销毁连接重连 |
| 指数五档垃圾值 | 按代码规则识别指数，盘口置空 |
| 港股/美股/期货 | 不在范围（只做 A 股）；7727 也不接入 |
| 非官方协议 | 仅供学习；服务端随时可能改，商用需自行评估 ToS |
